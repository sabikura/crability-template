# {{project-name}}

A pure-capability bare-metal application for Arm Morello, generated by `crability new-project`
{%- if platform == "qemu" %} for CHERI QEMU.
It boots on the `virt` machine with a Morello CPU: QEMU enters the ELF at EL2, where a small
stub (`src/el2/entry.S`) drops into pure-capability EL1 and `aarch64-purecap-rt` takes over
and calls `main`.
{%- elsif platform == "qemu-el1" %} for CHERI QEMU.
It boots on the plain `virt` machine with a Morello CPU: QEMU enters the ELF at EL1 in A64,
directly into `aarch64-purecap-rt`'s `_el1_entry`. The runtime is built with its `hybrid`
feature, which prefixes the entry with an A64 prologue that enables capability instructions
and switches to C64, so no boot shim or EL2 stub is needed before `main`.
{%- else %} for the Morello FVP.
It boots as BL33: a small EL2 stub (`src/el2/entry.S`) drops into pure-capability EL1, where
`aarch64-purecap-rt` takes over and calls `main`.
{%- endif %}

## Toolchain

The project does not use rustup. `.cargo/config.toml` points cargo at the wrapper scripts in
`toolchain/`, which run the Morello-enabled compilers:

- `rustc.sh` and `cargo.sh` run the Rust fork built by `crability rust`
- `clang.sh`, `ld.sh` and `objcopy.sh` run the Morello SDK tools built by `crability llvm`

All of them resolve from the crability bin dir, where the crability commands symlink the
binaries they build. The path baked in at generation time comes from the crability
configuration and can be overridden per shell with the `CRABILITY_BIN` environment variable.

## Building

Any host cargo works, since the config file redirects rustc and the linker:

```shell
cargo build --release
```

or, to run the pinned toolchain's cargo from anywhere:

```shell
crability cargo build --release
```

## Running on QEMU

Install CHERI QEMU with `crability qemu-install`, then boot with:

```shell
cargo run --release
```

`run-qemu.sh` is set as the cargo runner; it runs
`qemu-system-morello -M virt{% if platform == "qemu" %},virtualization=on{% endif %} -cpu morello -nographic -semihosting -kernel <elf>`
and can also be invoked directly (the ELF path as the first argument, the QEMU location via
`CRABILITY_BIN`, where `crability qemu-install` symlinks it). The program prints on the virt machine's PL011 UART at `0x09000000`, which
QEMU wires to the terminal, and terminates QEMU through a semihosting SYS_EXIT call when it
is done. Leave a still-running guest with `ctrl+a x`.

## Testing on QEMU

```shell
cargo test --release
```

Integration tests live in `tests/` with `harness = false`: each one is a bare-metal binary
that boots on QEMU through the same runner. The `test_assert!` and `test_assert_eq!` macros
from the library report failures over the UART and terminate QEMU with a non-zero exit code,
which `cargo test` picks up as a test failure; falling through to `qemu::exit(0)` reports
success. A panic exits non-zero as well.

Note that CHERI QEMU's `-M morello` board is not the Morello SoC: it is a bare testing board
for the Arm ACK with no UART, so nothing can print there. The `virt` machine is the supported
way to run Morello code in QEMU, which is why the UART and RAM addresses differ from the FVP.
{% else -%}
## Running on the FVP

The resulting ELF targets the memory map from `memory.x` (RAM at `0xE0000000`, where Arm
Trusted Firmware loads BL33). Package it as the BL33 payload of a FIP image and boot it with
the Morello FVP, installed via `crability fvp-install`. See the `aarch64-purecap` repository's
`examples/fvp` for the firmware packaging scripts.
